# Contributing to Markdawn

## pnpm Version

This project pins **pnpm to `10.28.2`** across all environments: local machines, VMs, and Docker containers. The lockfile must be produced and consumed by the same pnpm version, otherwise `pnpm install --frozen-lockfile` fails in the Docker build.

**The pinning is in the Dockerfile** — both `deploy/Containerfile.api` and `deploy/Containerfile.collab` pin via corepack:

```dockerfile
RUN corepack enable && corepack prepare pnpm@10.28.2 --activate
```

## Setting Up pnpm Locally

If you do not have pnpm 10.28.2 installed:

```bash
# Using corepack (recommended)
corepack enable
corepack use pnpm@10.28.2

# Verify
pnpm --version  # should print 10.28.2
```

If corepack is not available:

```bash
npm install -g pnpm@10.28.2
```

After switching pnpm versions, re-run `pnpm install` to regenerate the lockfile if needed.

## Why This Matters

`pnpm install --frozen-lockfile` (used in the Docker build) validates that the lockfile was generated by the same pnpm version. Mismatches cause `ERR_PNPM_LOCKFILE_CONFIG_MISMATCH` and break the deploy. Pinning to 10.28.2 everywhere ensures the lockfile is always compatible.

## What to Do After Pulling New Code

```bash
git pull origin master
pnpm install
pnpm build
```

If you see lockfile warnings or the install fails with a mismatch error, re-sync:

```bash
pnpm install --no-frozen-lockfile
pnpm install
```

Commit the updated lockfile only if it was legitimately changed by dependency updates — not as a routine sync step.
